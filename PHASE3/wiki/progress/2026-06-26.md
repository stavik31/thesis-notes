# 2026-06-26 — GAT Teaching Session

## What was covered

Teaching session on GNNs and GATs before writing Stage 3 code. No code written today — the goal was conceptual understanding first.

**Starting point:** user watched a video on GNNs and arrived with the basic message-passing picture (neighbour messages → weight matrix → non-linear activation → new node representation). Correct foundation.

**Concepts walked through, in order:**

**Weight matrices.** A weight matrix is just a matrix of learnable parameters — the same W as in `y = Wx + b` in any dense layer. After a node aggregates neighbour messages, it passes the aggregate through W to transform it into a new representation. Nothing GNN-specific; backprop updates it the same way.

**Message passing — refinement.** A node's new representation combines (1) its own current features and (2) the aggregated neighbour messages, both passed through the weight matrix. After L layers, the node has absorbed L-hop neighbourhood context.

**Embeddings — two distinct senses:**
- *Node embeddings (Sense 1):* the learned dense vector representation each node ends up with after message passing. Output of the GNN, not predefined.
- *Vehicle-type embedding table (Sense 2):* `nn.Embedding(5, 16)` — a lookup table mapping each vehicle type index to a learned 16-dimensional vector. This is a mode selector, not historical data.

**Why the type embedding goes in before the attention calculation.** Attention weights α_ij determine how much node i listens to neighbour j. If the type embedding conditions those weights, the model can learn to weight neighbourhoods differently per type (e.g. motorcycles → attend more to junction-heavy urban segments; HGVs → attend more to rural A-roads). Adding the type embedding after attention would mean the attention was computed blind to type — the neighbourhood aggregation would be identical for all types, just tagged differently at the end.

**Why crash counts + type embedding are both needed.** Crash counts in node features = historical evidence (per-segment, different per node). Type embedding = the current query / mode ("right now we're computing motorcycle risk"). Without the embedding, the model sees all five types' crash history simultaneously and has no mechanism to shift its computation based on which type is being queried.

**Why stack multiple GAT layers.** Each layer expands the receptive field by one hop. Two layers → a node sees its neighbours' neighbours, capturing spatial context beyond immediate adjacency (e.g. a dangerous junction two segments away still affects the risk picture). Start with 2.

**Oversmoothing.** Too many layers → every node's representation converges toward the same average → segment differences wash out. Fatal for this thesis, which depends on discriminating between segments. 2 layers is the right starting point for a dense urban network.

**GAT vs basic GNN.** Basic GNN aggregates neighbours equally (sum/mean). GAT learns per-edge attention weights α_ij, so more relevant neighbours get higher weight. For a road network: a motorway slip road is a more relevant HGV-risk neighbour than a residential side street; GAT can learn that distinction from the data.
