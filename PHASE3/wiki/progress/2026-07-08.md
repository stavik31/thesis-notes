# 2026-07-08 — Stage 3 complete, run nationally, live in production

Finished the guided section-by-section rewrite of `code/stage3_gat_risk_model/train.py`
(GAT → per-type cluster+share+XGBoost) that we began 2026-07-06. The engine is now
implemented, run on all of Great Britain, and its output is the production risk surface.
See the blueprint [[wiki/build/stage-3-cluster-share-engine]] and the engine rationale
[[wiki/concepts/vehicle-type-risk-divergence]].

## What was built (train.py, 8 sections)
1. constants (HISTORY 2020–21 / TARGET 2022–23 / HOLDOUT 2024 windows, MIN_CRASHES=30)
2. `load_data` (+ `--city`), 3. `severity_matrix` (crash grids, disjoint years = leakage guard),
4. `build_adjacency` (CSR) + `bfs_clusters` (densest-first BFS), 5. `cluster_frame` +
`cluster_target_share` (share label), 6. `road_class_onehot` + `build_type_features`,
7. `fit_predict_type` (5 fully independent XGBoost models), 8. `main` + output.
Output contract unchanged: `risk_scores.csv` = `(segment_id, vehicle_type, risk_score)`,
so Stage 4/5 consume it with no change. Also writes `risk_feature_importance.csv`.

## DECISION — objective `reg:squarederror` → `reg:logistic`
The first run produced risk scores slightly **outside [0,1]** (e.g. car min −0.076). Root
cause: squared-error is an **unbounded** regressor, but the target is a **share ∈ [0,1]**;
near the many ~0 targets the additive trees overshoot below zero. Clipping was rejected as a
band-aid (it masks the cause and perturbs ranks by tying at the boundary). **Fix: use
`reg:logistic`** — a sigmoid output bounded to (0,1) by construction, and cross-entropy is
the statistically correct loss for a proportion. **Verified, not assumed:** a Manchester
holdout gives *identical* metrics to squared-error (cross-type ρ = −0.038 both; validity
matched within noise — cycle .167→.168, lgv .093→.094, hgv .131→.137). Both are **rank-based**
metrics, so the small overshoot never affected any prior validated result; this was an
output-range/interpretability fix, not a correctness fix. Values differ in raw scale, not in
rankings — confirmed by the unchanged validity (validity is the referee for "does the model
know something different": it didn't).

## Two clarifications logged (from Q&A)
- **Routing will NOT diverge everywhere.** Stage 5 normalises risk **per type**, so absolute
  magnitude is moot — only spatial *contrast* matters. Routes diverge where a path passes a
  type-specific hotspot; elsewhere they collapse to shortest-time (correct behaviour). Because
  moto↔cycle and lgv↔hgv colocate (CLQ), expect **~3 route-families (car / two-wheeler /
  freight)**, matching the earlier ~3.1/5-distinct routing test. Quantify on the Stage-5 re-run.
- **The richer Stage-2 features** (`road_function`, `form_of_way`, `trunk_road`,
  `junction_degree`, pedestrian crossing) are **NOT model inputs** (they don't help prediction /
  risk explaining noise) — they feed the **separate, offline explainability layer**
  (`road_association.py`, `explain_route.py`), still in the test folder, not yet folded in.
