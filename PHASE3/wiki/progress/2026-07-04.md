# 2026-07-04 — Supervisor meeting: strategic fork resolved via a third path (clustering), not a direct pick

Direct continuation of [[wiki/progress/2026-07-03]], which ended with an open fork logged for
this meeting: formalize the ad hoc statistical smoothing estimate (best ρ, uncited) vs. ship the
GAT-stacked engine (worse ρ, fully defensible). Talking points brought into the meeting:
`/home/vik-esoc/Desktop/thesis/supervisor-notes-2026-07-03.md`.

## What happened

The supervisor did not pick one of the two engines directly. Instead he redirected the framing:
the reason every method (GAT, XGBoost, Empirical Bayes) struggles is the same root cause —
96–99.8% of segments have zero recorded crashes for a given vehicle type, so there is nothing for
any method, statistical or learned, to estimate from at raw segment resolution. His steer:
**pool segments into per-type clusters before estimating risk**, so estimation has enough data to
work with at all, then let the existing evaluation pipeline (cross-type ρ, hotspot Jaccard, CLQ)
decide — at the cluster level — whether the simple statistical estimate still wins or whether a
model is actually warranted there.

This reframes the 2026-07-03 fork rather than resolving it as originally posed: it isn't
"statistical vs. GAT" as competing finished engines anymore. It's a new step (cluster construction)
inserted before that choice, with the choice re-tested at a resolution where it's actually
answerable with enough data either way.

## The resulting plan

Full draft: `/home/vik-esoc/Desktop/thesis/new-direction-plan-2026-07-04.md` (repo root, working
doc, not yet copied into `raw/` — draft skeleton per its own header, meant to be edited before
being executed). Eight steps, summarized:

1. **Per-type clustering features** — for every segment in the network (not just crash sites):
   road class/function/form-of-way, segment length, and that type's **own** AADF (not shared
   traffic volume). Directly continues the 2026-07-03 rule that any type-agnostic signal collapses
   divergence — the clustering input itself must be type-specific from step one.
2. **5 independent clusterings** (hierarchical/agglomerative, one per type, not a shared
   clustering reused across types) — cut each type's tree based on data sufficiency (minimum
   crashes per cluster for a stable estimate, reasoning from the NB-dispersion math already used
   in the 2026-07-03 EB test), not an arbitrary K. Granularity is expected to differ sharply by
   type (car: many fine clusters; HGV: few, coarse ones).
3. **Estimate risk per cluster, per type** — pooled/statistical estimate first (severity-weighted
   count normalised by pooled exposure), before any model. If an EB-style prior is used at all,
   guard against it leaning on traffic volume as the dominant covariate (the exact 2026-07-03
   collapse mechanism).
4. **Test before building further** — rerun the same cross-type ρ / top-N Jaccard / CLQ metrics
   from 2026-07-03 on the cluster-derived, segment-assigned risk surface. Explicit gate: don't
   build a cluster-level model unless the simple estimate demonstrably falls short here.
5. **Model only if Step 4 says so** — GAT/XGBoost per type, at cluster (or within-cluster)
   resolution, which is a much smaller, denser problem than raw segment-level prediction.
6. **Separate spatial grouping for routing search efficiency** — a second, purely geographic
   grouping (grid/geo-clustering), independent of the feature-based risk clusters, to narrow
   search space for national-scale routing. Feature clusters can be geographically scattered by
   design (that's what lets sparse segments borrow from similar-but-distant ones); a routing
   search needs contiguous regions. Flagged as an assumption, not yet confirmed by the supervisor.
7. **Stage 5 routing unchanged** — same `segment_id, vehicle_type, risk_score` format `route.py`
   already consumes; only the risk-estimation layer feeding it changes.
8. **Evaluation** — same divergence metrics as 2026-07-03 for direct comparability, **plus a new
   held-out-block sparsity test**: hide a contiguous block's own crash history and its neighbors',
   estimate risk from the cluster method alone, check against real known values. This is the first
   test that actually validates whether clustering solved the coverage problem, rather than just
   measuring divergence in-sample. Then re-run the 2026-07-02 Phase A/B routing experiments on the
   new surface (all prior routing numbers are on the old, collapsed surface).

## What's still genuinely open (not resolved in this meeting)

Two questions inside the plan are marked for supervisor input with defaults assumed, and — unlike
the overall direction — **these were not actually discussed/confirmed**:

1. **Step 6**: is the geographic routing-search grouping meant to be separate from the
   feature-based risk clusters (Steps 1–3), or the same clusters reused? Plan assumes **separate**.
2. **What "zoom in" routing means**: computational pruning of the search space only (assumed), or
   a genuine two-stage decision where the coarse cluster constrains the fine search (which could
   produce suboptimal routes if a good path crosses a coarse region ruled out early)?

Both need explicit follow-up before Step 6/7 are built as final, not just assumed defaults.

## Why this doesn't undo the 2026-07-03 findings

- The niche (vehicle types crash in different places) is untouched — still the strongest-evidenced
  part of the thesis.
- The general mechanism (any type-agnostic/shared signal collapses divergence) is the reason
  Step 1's "own AADF, not shared" and Step 2's "5 independent clusterings" are non-negotiable
  design constraints, not stylistic choices.
- "Don't assume ML helps — test it" (the 2026-07-03 lesson that beat GAT/XGBoost/EB with an ad
  hoc smoothing baseline) is now a formal gate (Step 4) instead of a one-off finding.
- The EB-shrinkage caution (regressing on traffic-volume-shaped covariates collapses divergence)
  carries forward explicitly into Step 3.

## Decisions extracted

- **The 2026-07-03 fork (statistical vs. GAT-stacked) is superseded, not answered** — clustering
  is the new intermediate step, and the choice will be re-made at cluster level using the existing
  evaluation pipeline once real numbers exist. Documented in
  [[wiki/concepts/vehicle-type-risk-divergence]].
- **positioning-memo's "Separate models per type vs unified" row** (still marked "under revision"
  from 2026-07-03) updated to reflect this — see [[PHASE3/positioning-memo]].
- Two implementation questions (Step 6 clustering split, "zoom in" semantics) remain open and are
  not to be treated as supervisor-confirmed just because the plan states a default.

## Next

3. Build Steps 1–4 (clustering + pooled statistical estimate + evaluation gate) before touching
   Step 5 (cluster-level model).
4. Get explicit supervisor input on the two open sub-questions before finalizing Steps 6–7.
