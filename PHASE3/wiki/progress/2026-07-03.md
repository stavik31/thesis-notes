# 2026-07-03 — Full model-vs-statistics investigation; GAT type-collapse solved (partially); EB
shrinkage tested and beaten; Task B killed; strategic fork reached ahead of supervisor meeting

Direct continuation of [[wiki/progress/2026-07-02]] (which ended with: routes diverge under
capping + per-type norm + λ≈2, but only modestly; raw STATS19 shows the niche is real; the GAT
smooths a near-orthogonal ground truth into ρ=0.855 — "type-collapse"). This session is the full
diagnostic chase to fix type-collapse, tested every reasonable lever, and landed on a real
strategic decision point. All tests below are on **London** (bbox subset) unless noted; earlier
0.855/0.894-scale numbers differ slightly between runs due to slightly different active-segment
sets across scripts — treat all numbers as same-order-of-magnitude comparable within this session,
not decimal-precise across every script.

**Headline: the niche is confirmed further (raw truth ρ≈-0.05, ~4% hotspot overlap between
types — stronger than Lee 2018). Every model tested underperforms a simple statistical
smoothing estimate at preserving that divergence, including a proper Empirical Bayes
implementation. The best GAT variant (0.377) uses no new input data — the fix was training
design (objective + architecture), not richer features. A parallel "ML for conditional risk"
idea was tested and killed (negligible effect size). Ends in an open strategic fork: statistical
engine (best number, uncited) vs GAT-stacked engine (worse number, fully defensible) — logged
in `/home/vik-esoc/Desktop/thesis/supervisor-notes-2026-07-03.md` for tomorrow's meeting.**

## Test 1 — GAT architecture ladder (isolating architecture from objective)

All on raw per-type severity-weight counts (Poisson NLL), same 17-dim base features + per-type
`hist` feature already in the pipeline.

| variant | ρ | note |
|---|---|---|
| CURRENT (original: shared head, shared backbone) | **0.894** | baseline |
| PERHEAD (shared backbone, 5 separate output heads) | 0.816 | small gain |
| SEPARATE (5 fully independent GAT models, max decoupling) | 0.785 | barely better than PERHEAD |

**Conclusion: architecture decoupling alone saturates quickly and isn't the dominant lever.**
Going all the way to 5 independent models (5x params) barely beat per-head. Points at the
*objective*, not the architecture, as the bigger problem.

## Test 2 — does a clean, already-divergent target survive?

Built a 2-hop spatially-smoothed target (ρ=0.221, still genuinely divergent, denoised) and
retrained the ORIGINAL GAT architecture on it (MSE regression to that target). Result: model
output ρ = **0.928** — *worse* than the raw-count baseline (0.894), and worse than what it was
given. **A model that was just "smoothing via message-passing" would roughly preserve a clean
input like this. It didn't — it actively destroyed it.** This ruled out "sparse noisy target"
as the root cause and pointed hard at the shared-objective/shared-architecture combination.

## Test 3 — GNN vs non-graph vs statistical (3-way, same features/target where possible)

- **EXP1 — GAT, reframed to predict per-type SHARE** (composition, 5 numbers summing to 1, of the
  2-hop-smoothed target), MSE loss: pred ρ = **0.563**. (Share target itself: ρ=-0.134, i.e. still
  divergent — model smooths it but far less than on raw counts.) **Biggest single GAT-side lever
  found up to this point.**
- **EXP2 — XGBoost, non-graph, same base features + hist, raw-count target:** ρ = **0.748** vs
  GAT's 0.894 on identical inputs/objective. Isolates the graph itself: message-passing costs
  ~0.15 of the collapse, real but not dominant.
- **EXP3 — statistical, no model:** raw hist ρ=-0.006, 1-hop smoothed ρ=0.191, 2-hop smoothed
  ρ=0.221. **Every statistical variant already beat every model variant tested to this point.**

## Test 4 — data inventory (before assuming "richer features" would help)

Read every column in STATS19 (collision/vehicle/casualty tables, ~99 cols total) and OS Open
Roads `road_link` layer. Pipeline (`stage1_data_prep/prepare.py`) had been using `usecols=` to
load only 6 of ~99 available columns. Categorized:
- **Tier 1 (network-wide, all 3.96M segments, from OS):** `form_of_way`, `road_function`,
  `primary_route`, `trunk_road`, `road_structure`. Clean, 100% coverage.
- **Tier 2 (STATS19 collision-level, only exists at crash sites):** `road_type`, `speed_limit`,
  `junction_detail`, `junction_control`, `urban_or_rural_area`, `light_conditions`,
  `weather_conditions`, `road_surface_conditions`.
- **Tier 3 (crash-outcome/driver — NOT usable as risk-prediction inputs, only knowable after a
  crash):** `vehicle_manoeuvre`, `first_point_of_impact`, `age_of_driver`, etc. Excluded on
  principle throughout.

## Test 5 — XGBoost + "rich" features, v1 (FLAWED — caught a real leak)

First pass: XGBoost per type, BASIC (5 cols: road_class/length/AADF/centroid) vs BASIC+RICH
(Tier 1 + Tier 2, STATS19 context joined with **no year restriction**). BASIC ρ=0.650,
RICH ρ=**0.329** — looked like a big win.

**Caught the problem:** the STATS19 join included crashes from 2022–2024 — i.e. the target
window and the holdout year. Not a leak in the main pipeline (which already has proper
`HISTORY_YEARS`/`TARGET_YEARS` discipline) — a leak in this one scratch test, which didn't
replicate that discipline.

## Test 6 — feature ablation, corrected for the leak (still all-years, isolating WHICH field)

To find the leak's exact source: BASIC / OS_ONLY (clean, 100% coverage) / FLAG_ONLY (single bit:
"has any STATS19 record") / S19_ONLY / BOTH — still using the leaky (all-years) STATS19 join at
this stage, deliberately, to isolate content vs. presence:

| variant | dims | ρ |
|---|---|---|
| BASIC | 5 | 0.650 |
| OS_ONLY (clean, no leak) | 9 | 0.681 (no help) |
| FLAG_ONLY (has-record bit, LEAKY) | 6 | 0.306 |
| S19_ONLY (LEAKY) | 10 | 0.327 |
| BOTH (LEAKY) | 14 | 0.329 |

**FLAG_ONLY alone — a single content-free bit — reproduced almost the entire "improvement."**
Confirmed: the win in Test 5 was ~90% leak, not content. OS_ONLY (the only clean variant here)
showed no real improvement over basic.

## Test 7 — GAT with rich (clean OS-only) features

Retrained the ORIGINAL GAT architecture with the clean OS fields (`form_of_way`, `road_function`,
`primary_route`, `trunk_road`) appended to node features (17→33 dims), raw-count objective:
ρ = **0.822** vs 0.894 baseline. Small, real, not decisive — consistent with OS_ONLY's flat
XGBoost result.

## Test 8 — crash-context test, PROPERLY leak-free this time

Restricted STATS19 context join to `HISTORY_YEARS=[2020,2021]` only (matching the pipeline's
existing convention), target strictly `[2022,2023]`. Tested PLACE (road_type/junction/urban),
SPEED (speed_limit), CONDITIONS (light/weather/surface), FLAG, COMBINED — all still
**type-agnostic** (built from ANY vehicle's crash at that segment, not filtered by type):

| variant | ρ |
|---|---|
| BASIC | 0.650 |
| FLAG (has pre-2022 record, type-agnostic) | 0.794 |
| PLACE | 0.787 |
| SPEED | 0.791 |
| CONDITIONS | 0.792 |
| COMBINED | 0.785 |

**Every one made things WORSE than basic, and they all cluster tightly (0.785–0.794) regardless
of content.** Coverage was only 11.5%. Diagnosed mechanism: a signal that's **equally
informative for all 5 types** (generic "this location has crashed before") pulls all 5 per-type
models toward the same shared answer — literally the same collapse mechanism as the GAT's
shared backbone, replaying in a completely different, non-graph model.

## Test 9 — type-specific version of the same information (THE FIX for XGBoost)

Same fields, but computed **per type** — e.g. "did a cyclist crash here pre-2022" instead of
"did anyone." Own-type history (severity count) and own-type context (road/junction/weather at
that type's own past crashes):

| variant | dims | ρ |
|---|---|---|
| BASIC | 5 | 0.650 |
| TYPESPEC_HIST (own-type history count) | 6 | **0.552** |
| TYPESPEC_CONTEXT (own-type road/weather context) | 14 | 0.553 |
| TYPESPEC_COMBINED | 15 | 0.554 |

**Confirmed mechanism precisely: same underlying information, packaged type-specifically instead
of type-agnostically, flips from actively harmful (0.79) to the best non-graph result found
(0.55).** Also: `TYPESPEC_CONTEXT` added almost nothing beyond `TYPESPEC_HIST` alone — the
categorical road/weather content is largely redundant with "did this type crash here before,"
not new information. `TYPESPEC_HIST` is, structurally, the same signal the GAT's own `hist`
feature already provides — meaning the GAT already had access to a working signal and still
collapsed on it (ties back to Test 2).

## Test 10 — STACKED GAT: share-target objective + per-head architecture together

Combined the two validated GAT-side levers (Test 1's per-head, Test 3's share-target), **same
base features as the original baseline — no new input variables added.**

| model | ρ |
|---|---|
| GAT raw (baseline) | 0.894 |
| GAT share-only | 0.563 |
| GAT perhead-only | 0.816 |
| **STACKED (perhead + share-target)** | **0.377** |

**Synergistic, not additive** — naive sum of the two individual effects would predict ~0.48; got
0.377. Best model result of the entire investigation. Mechanism: share-target forces the
backbone to represent *relative* type differences; per-head removes the final shared-output
bottleneck that would otherwise re-collapse that differentiated signal. Removing both
constraints together compounds.

## Test 11 — end-to-end: stacked GAT through Stage 4 + Stage 5

Retrained stacked GAT, converted predicted share → pred_count via `share × 2-hop-smoothed-total`
(the count+proportion coupling Lee 2018's own limitations section recommends), built a
risk_scores-equivalent table, ran through Stage 4's actual `filter_risk_surface`/`run_clq`
functions (self-calibrated caps, verified sane: exactly 15% hotspots per type, non-degenerate
cap values) and a 10-route London Stage-5-equivalent routing test (cap=p99, global norm, λ=2):

| metric | old GAT (raw) | stacked GAT |
|---|---|---|
| cross-type ρ | 0.894 | 0.377 |
| CLQ pairs diverging | 0/10 | 0/10 (unchanged) |
| routing mean distinct paths /5 | 1.00 | 2.00 |
| routing mean route Jaccard overlap | ~1.00 | 0.87 |

**Real, measurable routing improvement. But CLQ (hotspot-tail divergence) didn't move at all** —
confirmed the caps were self-calibrated correctly (not a stale-cap artifact), so this is genuine:
the improvement lives in the mid-range of the risk distribution, not in each type's *most*
dangerous segments — which is arguably what routing cares about most.

## Test 12 — Empirical Bayes shrinkage (the literature-standard method) — beaten by the ad hoc smoothing

Implemented properly: Poisson-GLM Safety Performance Function (SPF) per type on
`log(AADF)+log(length)`, NB dispersion via method-of-moments, Hauer's classical EB combining rule
(`w=1/(1+alpha*mu)`, `EB = w*mu + (1-w)*y`) — this is the Pathivada-2025-style method, the
citable literature-standard approach.

Result: ρ = **0.412** — **worse** than the ad hoc 2-hop spatial smoothing (~0.19–0.25 depending
on exact run) and worse than the stacked GAT (0.377). Diagnosed: EB's "prior" is a regression on
generic exposure covariates (AADF, length) — a relationship that's similar in *shape* across
types — so it shrinks sparse/low-count segments (most segments) toward a shared, non-divergent
baseline. **Same collapse mechanism as Tests 8 and Test 1/2, a fourth independent confirmation,
this time in a "proper," fully citable statistical method.** Corrected an earlier assumption
(made mid-session) that the textbook method would do at least as well as the ad hoc one — it
didn't, and now there's a clear, evidenced reason why.

**Open item, not yet done:** the ad hoc spatial-smoothing method that's been winning all
session was never properly grounded in a citable method. Best guess: **Network KDE**
(kernel density estimation constrained to the road network — Okabe & Sugihara framework; applied
to traffic accidents specifically in some existing literature) is very likely the correct citable
home for this — **not verified**, flagged explicitly as a to-check item, not asserted as done.

## Test 13 — Task B premise check: conditional (weather/light/surface) risk by vehicle type

Before building a case-crossover + ML pipeline for "risk conditional on driving conditions"
(the professor's original framing, and Wei 2024's case-crossover design as the intended method
for handling the missing weather-specific exposure data), checked whether the premise even holds:
chi-square + Cramér's V, vehicle_type × {light_conditions, weather_conditions,
road_surface_conditions}, n≈870–885k crash-vehicle rows.

| condition | χ² | p | Cramér's V |
|---|---|---|---|
| light | 8,864 | ~0 | 0.050 |
| weather | 3,037 | ~0 | 0.029 |
| road surface | 3,981 | ~0 | 0.034 |

All "significant" only because n is huge; **effect sizes are all below the 0.1 "negligible"
threshold.** Real, sensible directional patterns exist (cyclist share 10.0%→1.4% daylight→snow;
motorcycle share 9.7%→2.3% fine→snow) but they're small. **Task B killed** — not an ML failure,
the underlying pattern itself is too weak for any method to exploit as a real second pillar.

## Decisions extracted

- **Corrected assumption:** EB shrinkage (literature-standard) does NOT beat the ad hoc spatial
  smoothing — it does notably worse, for a diagnosable reason (generic covariate prior = same
  collapse mechanism as everything else this session). Documented so this isn't re-assumed later.
- **Confirmed, repeatedly, across 4 independent settings:** any signal shared equally across
  types (shared GAT output head, shared backbone, type-agnostic input feature, EB's generic
  covariate prior) collapses divergence. Type-specific packaging of the *same* information fixes
  it. This is now the central mechanistic finding of the whole investigation — see
  [[wiki/concepts/vehicle-type-risk-divergence]] (needs updating with this).
- **The "richer inputs" hypothesis for why ML should beat statistics was tested directly and
  did not hold.** The best GAT (0.377) used identical inputs to the worst GAT (0.894) — the win
  was training design, not data. Genuinely new features (OS geometry, STATS19 context) mostly
  didn't help, or only matched what an existing feature (`hist`) already provided.
- **Task B (conditional ML) is dead.** Premise tested, negligible effect size.
- **Open strategic fork, not yet resolved:** statistical engine (best ρ, needs Network-KDE-style
  literature grounding before it's citable) vs. GAT-stacked engine (worse ρ, fully defensible
  right now, complete rigorous story). Logged for supervisor discussion — see
  `/home/vik-esoc/Desktop/thesis/supervisor-notes-2026-07-03.md` (repo root, not wiki — working
  notes for the 2026-07-04 meeting, not itself a wiki page).
- **The core niche premise is not what's in question** — it's the strongest-evidenced part of
  the whole thesis at this point (raw truth ρ≈-0.05, 4% hotspot overlap, beats Lee 2018's
  zone-level evidence). What's undecided is only which engine powers the system.
