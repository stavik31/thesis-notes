# 2026-05-25 — RAG Offline Phase Complete

## What was done

Built the offline phase of the RAG pipeline: `rag/build_index.py`. This script encodes the full train+val corpus into a FAISS index and saves all necessary files to disk.

**Key decisions made during this session:**

- **Corpus: train + val splits only (478,301 records).** Test split excluded from the index to prevent retrieval contamination during evaluation — if test records were in the index, querying with a test crash could retrieve that exact crash back, trivially inflating evaluation quality metrics.
- **Sentence transformer: `all-MiniLM-L6-v2`.** Pre-trained, no retraining required. Produces 384-dim dense vectors purpose-built for semantic similarity search. Separate from Gemma's internal embedding space — Gemma never sees vectors, only retrieved text.
- **FAISS index type: `IndexFlatL2`.** Exact nearest-neighbour search. Sufficient for 478k vectors at query time.
- **Embedding cache:** embeddings saved to `embeddings.npy` on first run; loaded from disk on subsequent runs to avoid re-encoding.
- **Live API integration deferred:** for the thesis prototype, query input is a narrative constructed from a test-split crash record. The system is architecturally identical whether the query comes from a pre-built narrative or a live GPS + weather API call — the input layer is the only difference. Live API integration noted as future work.

## Concepts clarified

- RAG has no training process. The offline phase is pure inference (encoding) + data structure construction (FAISS index).
- The sentence transformer and Gemma operate in completely separate spaces. FAISS returns text, not vectors, to Gemma.
- Contamination in RAG evaluation only matters if test records are in the retrieval corpus. Excluded here.
