# 2026-04-30 — Supervisor Meeting: New Directions

## What Happened

Met with supervisor. Two major directions were introduced that reshape the project scope beyond pure CrashSage replication.

## Direction 1 — Correlation / Variable Analysis First

Before any modelling, conduct a structured analysis of the STATS19 data to understand which variables actually carry signal and whether the dataset is rich enough to support the intended task.

**The challenge:** STATS19 is hierarchical — one accident has many vehicles, each vehicle has many casualties. Naive flattening inflates correlations due to row duplication.

**Correct approach:**
- Analyse at **casualty level** (natural prediction unit): join casualty + vehicle + accident into a clean 1-row-per-casualty table. Run Cramér's V (categorical→categorical) and point-biserial (binary→continuous) against `casualty_severity`.
- Analyse at **accident level**: aggregate casualties/vehicles up (max severity, vehicle count, casualty count) then correlate with accident-level features.
- Flag near-zero-correlation features as candidates to drop. Flag high intercorrelation pairs (multicollinearity) for the modelling stage.
- Check everything against the class imbalance (Fatal=7k, Serious=110k, Slight=386k) — coefficients may be dominated by the slight class.

**Deliverable:** A ranked feature importance table at each level, plus a list of data gaps (fields that exist but carry no useful variance).

## Direction 2 — LLMs + Information Retrieval (RAG)

Supervisor suggested framing the LLM component as **Retrieval-Augmented Generation** rather than pure fine-tuning. Concretely:

- Given a new crash's structured features → retrieve K most similar historical crashes from STATS19.
- Use retrieved cases + the new crash's narrative as context for an LLM to reason about severity or contributing factors.

This is a distinct paradigm from CrashSage (which fine-tunes the LLM on crash narratives) and from Tab-Text (which fuses modalities at the embedding level). RAG keeps the LLM frozen and pushes the domain knowledge into the retrieval index — cheaper to update, more interpretable retrieval step.

The correlation analysis feeds directly into RAG design: the top-correlated features become the fields used to construct the similarity query and the narrative template.

## Direction 3 — Spatial / Location-Based Analysis

STATS19 has `latitude` and `longitude` on every accident record. Supervisor flagged this as an underexplored dimension.

**Approaches discussed:**
- **Hotspot detection:** Cluster crash coordinates (DBSCAN). Compare severity distributions inside vs. outside hotspots.
- **Spatial features as predictors:** Derive distance to nearest junction, urban/rural flag (verifiable against the raw field), proximity to prior high-severity crashes in a rolling window.
- **Spatial autocorrelation:** Moran's I to test whether severity clusters spatially — a strong result justifies location as a retrieval dimension.
- **Geo-aware RAG:** Retrieve similar historical crashes *within a spatial radius* of the query crash. This combines the correlation findings with the RAG framing.

External enrichment (road geometry, land use via OpenStreetMap/`osmnx`) is a possible extension — not a core requirement at this stage.

## Implications for the Project

The CrashSage replication is now **baseline context** rather than the primary implementation target. The revised project arc is:

1. **Data analysis phase:** Correlation analysis across all three levels. Spatial analysis. Establish which features matter.
2. **Baseline phase:** CatBoost + zero-shot LLM (already planned). These ground the comparison.
3. **RAG phase:** Build a retrieval index using top-correlated features (+ spatial). Evaluate against baselines.
4. **Extension phase (if time):** Compare RAG against fine-tuned CrashSage. Spatial-aware retrieval vs. naive retrieval ablation.

## Blockers / Open Questions

- RAG evaluation protocol: what is the right metric for retrieved-context LLM reasoning? Standard F1 applies to the final prediction, but retrieval quality needs its own measure (e.g. precision@K on severity-matched cases).
- Which embedding model for crash narratives in the retrieval index? FAISS + sentence-transformers is the obvious starting point.
- Does spatial proximity actually improve retrieval relevance, or do feature-based similarity already capture it?

## Next Steps

1. Download STATS19 and run the correlation analysis (casualty-level first).
2. Run spatial clustering on accident coordinates — confirm hotspots exist before investing in spatial features.
3. Draft RAG architecture sketch for supervisor review.
