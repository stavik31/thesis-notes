## What happened

First day of the wiki. Both foundation papers read and processed. Initial understanding of the domain formed.

## Compute

**RTX 5090, 32GB VRAM** (lab computer). Fine-tuning LLaMA3-8B with LoRA is feasible on this hardware. CrashSage used 4× A6000 48GB GPUs but with batch size 1 + gradient accumulation — same config works on a single 5090. May need to reduce max sequence length from 2048 → 1024 as a precaution. No compute constraint on the thesis.

## Key observations from the session

- Correctly identified the domain gap: both papers predict severity *outcomes*, not contributing factors or causation. The gradient attribution in CrashSage is a partial answer but it's post-hoc, not causal.
- Recognized that multi-modal approaches (Tab-Text) may not apply if data is already narrative — later clarified that data is STATS19 (structured tabular, 3 relational tables), so both approaches apply.
- Decided to build CrashSage on STATS19 first, then identify gap from implementation experience. Assessed as valid strategy.

## Dataset confirmed

**STATS19** — UK Department for Transport national crash database
- 5 years of data (~500k–700k crash records total)
- Three tables: `accidents`, `vehicles`, `casualties` — joins on `accident_index`
- 3-class severity: Fatal / Serious / Slight (unlike CrashSage's binary)
- UK-specific columns: speed zones, junction types, UK road geometry, UK vehicle codes

## Decisions made

- Build CrashSage pipeline on STATS19 as first implementation target
- Compute access needs to be confirmed before committing to fine-tuning
- Gap will be identified empirically through implementation, not purely from literature
