# 2026-05-21 — Phase 1 Complete: Three-Way Baseline Comparison

## What Was Done

Completed the full Phase 1 baseline evaluation: zero-shot Gemma, fine-tuned Gemma (LoRA), and XGBoost on tabular features — all evaluated on the same held-out test set (25,174 records, stratified 5% split, seed 42).

Also rewrote and debugged the zero-shot evaluation script (`llm/zero_shot.py`) after discovering the base model was producing freeform text and getting `Unknown` predictions. Fixed by adding "Reply with one word only." to the system prompt. Same prompt fix applied to `llm/evaluate.py` (fine-tuned) for consistency.

Built a new `llm/xgb_baseline.py` that trains XGBoost on the same collision_index-aligned test split as the LLM runs, replacing the old `xgb_collision.py` (which used a different 20% random split).

## Final Results

| System | Slight | Serious | Fatal | **Macro F1** |
|---|---|---|---|---|
| Zero-shot Gemma | 0.090 | 0.357 | 0.000 | **0.149** |
| XGBoost (tabular) | 0.686 | 0.285 | 0.078 | **0.350** |
| Fine-tuned Gemma | 0.690 | 0.383 | 0.152 | **0.408** |

---

## Key Observations

**Zero-shot never predicts Fatal.** Without domain adaptation, the base model has no concept of where the Fatal boundary is — it defaults to Serious for anything ambiguous. Fine-tuning unlocked Fatal recall entirely (0.000 → 0.152). This is the clearest evidence that domain adaptation was necessary.

**Fine-tuned Gemma beats XGBoost overall.** Macro F1 0.408 vs 0.350. The narrative captures factor interactions that tabular features miss, particularly for Serious and Fatal classes. Slight is essentially a tie (0.690 vs 0.686) — the narrative adds nothing for the easy majority class.

**Serious is the hard class for everyone.** All three systems struggle here. The boundary between Serious and the other classes is inherently ambiguous — the same road conditions can produce Slight or Serious outcomes depending on vehicle speed, age, and luck. This is a consistent finding across tabular and narrative approaches.

**XGBoost is a strong baseline.** It trains fast, uses no GPU, and nearly matches the fine-tuned LLM on Slight. For pure classification, XGBoost is the simpler and nearly-as-good choice. Its limitation is output format — it cannot generate explanatory text.

---

## Key Decisions

**Fine-tuned Gemma is the RAG backbone.** The classification results justify this: it outperforms zero-shot (domain adaptation works) and outperforms XGBoost (narrative-based understanding adds value). The margin isn't dramatic but it's consistent across all three classes.

**XGBoost stays as the tabular baseline for Phase 2.** The real Phase 2 comparison is: XGBoost (label only, no explanation) vs fine-tuned Gemma + RAG (grounded narrative warning). Classification F1 alone is not the final metric — warning quality, groundedness, and usefulness to a driver are the Phase 2 evaluation targets.

**Zero-shot drops out.** It served its purpose — proving fine-tuning was necessary. It won't be re-evaluated in Phase 2.

**Classification F1 is not the thesis claim.** The LLM is not justified because it dramatically outclasses XGBoost at classification. It is justified because it matches or beats XGBoost on understanding *and* can generate driver warnings that XGBoost fundamentally cannot produce.

---

## Evaluation Methodology Note

Initial zero-shot results (Macro F1 0.096) were misleading — ~21,000 of 25,174 records got `Unknown` predictions because the base model ignored the one-word instruction. Adding "Reply with one word only." to the system prompt fixed this. Both models now use identical prompts. A constrained decoding approach (logit masking to the three label tokens) was considered and rejected in favour of prompt fixing — simpler, interpretable, and standard practice for LLM evaluation.
